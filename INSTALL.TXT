BBS 빌드 / 업데이트 (update.sh)
==============
olddos 계정에서 BBS 홈의 update.sh 를 실행한다. 처음 빌드할 때도, 소스가 바뀐 뒤에도 같다.
% /home/olddos/olddos-bbs/update.sh

  하는 일
    1) git pull                  화면 파일(txt/), 메뉴(*.mnu) 는 이것으로 바로 반영
    2) /tmp/olddos-bbs-build 에 src 를 복사해 처음부터 make all
       (makefile 에 헤더 의존성이 없으므로 예전 .o 를 쓰지 않는다)
    3) 모두 성공했을 때만 바뀐 실행 파일을 bin/ 과 BBS 홈(ctime)에 반영, 바뀐 목록 출력

  - 빌드가 하나라도 실패하면 아무것도 바꾸지 않는다. 오류 줄을 보여 주고
    전체 기록은 /tmp/olddos-bbs-build.log 에 남는다.
  - 실행 파일은 임시 이름으로 복사한 뒤 mv 로 바꾼다. 접속 중인 사용자는 기존 프로그램을
    계속 쓰고 다음 접속부터 새 버전이 실행된다. BBS 는 따로 재시작할 것이 없다.
  - DB 테이블 변경(새 칸 추가 등)은 프로그램이 처음 실행될 때 자동으로 한다.

  옵션
% NOPULL=1 /home/olddos/olddos-bbs/update.sh
    git pull 을 건너뛴다 (서버에서 직접 고친 소스를 빌드할 때)
% /home/olddos/olddos-bbs/update.sh /다른/빌드/디렉터리
    빌드 디렉터리를 바꾼다 (기본 /tmp/olddos-bbs-build)

  손으로 빌드하려면 (빌드 결과가 바로 bin/ 에 들어간다)
% cd /home/olddos/olddos-bbs/src && make clean && make all

  쥬라기공원 머드는 src/jurassic/update.sh 로 따로 한다 (아래 머드 게임 연결의 8) 업데이트).

머드 게임 연결 (쥬라기공원 2)
==============
대문 7 번 [머드 게임] -> 2 번은 같은 서버에서 따로 띄운 머드에 연결한다.
BBS 는 bin/mudlink 로 127.0.0.1:4444 에만 접속시킨다. (포트는 hanulso.mnu 의 args)
비상업 용도로만 운영한다. (MudOS 라이선스)

src/jurassic 구성
  driver/  MudOS v22.2b14 (github.com/maldorne/mudos) + 한글 수정
           - packages/hangul.c : 한글 조사 efun (han_iga, han_obj, han_tool ...)
           - add_action.c      : 마지막 단어를 명령으로 ("칼 가져")
           - backend.c         : heart_beat 타이머 (glibc ualarm 문제)
           - local_options     : PACKAGE_HANGUL, INTERACTIVE_CATCH_TELL 등
  jp2_v15.tgz  원본 머드 라이브러리 (HanLP 쥬라기공원 2 복원판, 파일 내용 EUC-KR)
  libpatch/ 원본 위에 덮어쓰는 파일
           adm/master/efun/hanlp.c : 원래 HanLP 드라이버에 있던 함수들
           adm/wizard/하늘소, adm/config/groups : 운영자
  bin/     config.jurassic, startmud, killmud
  build.sh, deploy.sh, update.sh (받기/빌드/끄기/설치/시작 한 번에)

1) 빌드 도구
% yum install gcc bison
  (64 비트로 빌드한다. 문제가 있으면 BITS=32 ./build.sh 로 32 비트 빌드:
   이때는 glibc-devel.i686 libgcc.i686 도 필요)

2) 빌드 / 설치 (저장소의 소스만으로 된다)
% cd /home/olddos/olddos-bbs/src/jurassic
% ./build.sh /tmp/jurassic-build
% ./deploy.sh /home/olddos/jurassic /tmp/jurassic-build
  - build.sh  : driver/ 를 빌드 -> /tmp/jurassic-build/driver/driver
  - deploy.sh : jp2_v15.tgz 를 풀어 원본 라이브러리를 설치하고 libpatch 를 덮어쓴 뒤
                드라이버, 설정(bin/config.jurassic), startmud, killmud 를 /home/olddos/jurassic 에 둔다.
  - 다시 설치해도 lib/data (사용자 자료), lib/log 는 덮어쓰지 않는다.
  - 소스를 고친 뒤에는 git pull 하고 위 두 줄을 다시 실행, 머드를 다시 띄운다 (7 번).

3) BBS 쪽 연결 프로그램 (bin/mudlink)
% cd /home/olddos/olddos-bbs/src && make mudlink

4) 실행 (드라이버가 죽으면 10 초 뒤 다시 띄움)
% cd /home/olddos/jurassic/bin
% nohup ./startmud > /dev/null 2>&1 &
  부팅 때 자동 실행: /etc/rc.local 에
  su - olddos -c 'cd /home/olddos/jurassic/bin && nohup ./startmud > /dev/null 2>&1 &'
  (olddos 는 BBS 를 돌리는 계정. 머드를 root 로 돌리지 않는다)
  로그: /home/olddos/jurassic/lib/log/driver/

5) 확인
% telnet 127.0.0.1 4444
  외부에서 4444 번으로 바로 들어오지 못하도록 방화벽은 23 번만 열어 둔다.

6) 운영자 캐릭터 (하늘소)
  운영자 설정은 src/jurassic/libpatch 에 들어 있어 설치할 때 자동으로 적용된다.
    libpatch/adm/wizard/하늘소   : 운영자 명령 경로
    libpatch/adm/config/groups   : (root) 하늘소:운영자
  처음 한 번 게임에서 '하늘소' 캐릭터를 만들고 다시 접속하면 운영자 명령을 쓸 수 있다.
  ('시스템' 으로 확인)

7) 끄기 / 다시 띄우기
  끄기 (startmud 와 드라이버를 모두 끔):
% /home/olddos/jurassic/bin/killmud
  다시 띄우기 (드라이버만 끄면 startmud 가 10 초 뒤 다시 띄움):
% /home/olddos/jurassic/bin/killmud -r
  꺼 둔 머드 켜기:
% cd /home/olddos/jurassic/bin && nohup ./startmud > /dev/null 2>&1 &
  killmud 는 드라이버에 kill(SIGTERM) 을 보낸다. 드라이버는 접속자 자료를 저장하고 끝난다.
  (30 초 안에 끝나지 않을 때만 kill -9, 이때는 저장되지 않는다)
  게임 안에서는 운영자로 접속해서 '0 다운' (지금) 또는 '5 다운' (5 분 뒤, 접속자에게 알림),
  취소는 '중지 다운'. startmud 를 띄워 둔 채 '다운' 하면 10 초 뒤 자동으로 다시 뜬다.

8) 업데이트 (소스를 고쳤거나 저장소가 바뀐 뒤)
  olddos 계정으로 한다 (root 라면 su - olddos).

  한 번에 하기 (권장): 받기 -> 빌드 -> 끄기 -> 설치 -> 시작 -> 확인
% /home/olddos/olddos-bbs/src/jurassic/update.sh
    빌드는 머드를 끄기 전에 하므로 빌드가 실패하면 머드는 켜진 그대로 남는다.
    startmud 가 여러 개 떠 있어도 이 설치본의 것을 모두 찾아 끈다.
    끝에 127.0.0.1:4444 에 접속되는지 확인한다.
    NOPULL=1 (git pull 건너뜀), NOBUILD=1 (빌드 건너뜀, 게임 내용만 바뀌었을 때)
    설치/빌드 위치를 바꾸려면: update.sh [설치 디렉터리] [빌드 디렉터리]
    빌드 기록: /tmp/jurassic-build.log

  아래는 같은 일을 손으로 하는 방법이다.

  가) 머드를 끄고, 빌드하고, 설치하고, 다시 켜기 (엔진/설정을 고쳤을 때, 가장 확실한 방법)
% /home/olddos/jurassic/bin/killmud
    startmud 와 드라이버를 모두 끈다. 접속자 자료는 저장된다.
% cd /home/olddos/olddos-bbs && git pull
% cd src/jurassic
% ./build.sh /tmp/jurassic-build
    "빌드 완료" 가 나와야 한다. 게임 내용(libpatch)만 바뀌었으면 건너뛰어도 된다
    (단, /tmp/jurassic-build 가 남아 있어야 한다. 서버를 재부팅하면 지워진다).
% ./deploy.sh /home/olddos/jurassic /tmp/jurassic-build
    "설치 완료" 가 나와야 한다. 사용자 자료(lib/data)와 로그(lib/log)는 그대로 남는다.
% cd /home/olddos/jurassic/bin && nohup ./startmud > /dev/null 2>&1 &
% ps -ef | grep -E 'startmud|driver config.jurassic' | grep -v grep
    startmud 와 driver config.jurassic 두 줄이 보이면 정상.
    (CentOS 6 의 pgrep 은 -a 가 없다. pgrep -fl 'startmud|driver' 로도 볼 수 있다)
% telnet 127.0.0.1 4444
    접속 화면이 나오는지 확인. 안 뜨면 /home/olddos/jurassic/lib/log/driver/driver.err

  나) 켜 둔 채로 설치하고 다시 띄우기 (접속자가 있을 때 짧게 끊고 싶을 때)
% cd /home/olddos/olddos-bbs && git pull
% cd src/jurassic
% ./build.sh /tmp/jurassic-build
% ./deploy.sh /home/olddos/jurassic /tmp/jurassic-build
% /home/olddos/jurassic/bin/killmud -r
    (또는 하늘소로 접속해서 '0 다운') -> startmud 가 10 초 뒤 새 버전으로 다시 띄운다.
    머드가 실행 중이어도 설치된다.

  BBS 쪽 연결 프로그램이 바뀌었으면: cd /home/olddos/olddos-bbs/src && make mudlink

9) 게임 내용 고치기
  원본 게임 파일은 src/jurassic/jp2_v15.tgz 안에 있다 (HanLP/lib 아래).
  고칠 파일은 같은 경로로 src/jurassic/libpatch/ 에 넣는다.
    예) 원본 HanLP/lib/d/빌딩/로비.c  ->  src/jurassic/libpatch/d/빌딩/로비.c
  deploy.sh 가 설치할 때 원본 위에 덮어쓴다. (파일 내용은 EUC-KR 로)
  운영자 설정(adm/wizard/하늘소, adm/config/groups)도 이 방식으로 들어 있다.
  고친 뒤 8) 의 deploy.sh 와 '0 다운' (빌드는 엔진을 고쳤을 때만 필요)

머드 게임 연결 (무한대전)
==============
대문 7 번 [머드 게임] -> 3 번은 같은 서버에서 따로 띄운 무한대전에 연결한다.
BBS 는 bin/mudlink 로 127.0.0.1:4100 에만 접속시킨다. (포트는 hanulso.mnu 의 args 와
설치 디렉터리의 bin/port 를 같게)
무한대전은 Mordor 2.5 (Brett J. Vickers) 를 금오공대 네트워크 동아리가 한글화한 머드다.
원본: https://github.com/nicecapj/mudmuhan  비상업 용도로만 운영한다.

src/muhan 구성
  game/src       엔진 소스 (원본을 64 비트에서 돌도록 고친 것, EUC-KR)
  muhan_data.tgz 방/몬스터/물건/도움말/게시판 데이터 (원본 그대로, 파일 이름이 EUC-KR 이라 묶음)
  tools/         gen_disk32.py (disk32.c/h 를 만듦), layout_check.c (구조체 배치 검사)
  build.sh, deploy.sh, update.sh, bin/startmud, bin/killmud

64 비트로 옮기며 고친 것 (원본은 리눅스 커널 2.0, 32 비트)
  - 데이터 파일에 C 구조체를 그대로 저장한다 (room 480, object 352, creature 1184 바이트).
    disk32.c 가 읽고 쓸 때 32 비트 배치로 바꾼다. 원본 데이터 파일을 그대로 쓴다.
    32 비트 라이브러리(glibc-devel.i686)는 필요 없다.
  - print/logf 등 가변 인자를 int 매개변수로 흉내 낸 함수 -> long (포인터가 잘리지 않게)
  - 표준 헤더를 넣어 malloc 등이 int 로 잘리지 않게, logf/send 이름 충돌 정리
  - 127.0.0.1 에서만 접속을 받음, SIGTERM 에 접속자 저장 후 종료, SO_REUSEADDR
  - 운영자 이름: 하늘소 (원래의 테스토스/꽃/뽀뽀 는 지움. 비워 두지 않으면 아무나 그 이름으로
    가입해 운영자가 된다)

1) 빌드 도구
% yum install gcc make

2) 설치 / 업데이트 (olddos 계정)
% /home/olddos/olddos-bbs/src/muhan/update.sh
    받기 -> 빌드 -> 끄기 -> 설치 -> 시작 -> 127.0.0.1:4100 확인
    처음 실행하면 /home/olddos/muhan 에 데이터를 풀고 플레이어 폴더(player/가 ... 하, temp)를 만든다.
    그다음부터는 실행 파일만 바꾼다. 방/몬스터/물건(운영자가 게임 안에서 고칠 수 있음),
    플레이어, 게시판, 편지, 로그는 그대로 남는다.
    NOPULL=1 (git pull 건너뜀)
    세계 데이터를 원본으로 되돌리려면: RESET_WORLD=1 (rooms, objmon, help 만 다시 풂)
    공지: log/news (접속하면 모두에게), log/DM_news (운영자에게만). EUC-KR 텍스트로 서버에서
    바로 고치면 다음 접속부터 보인다. 도스박물관 기본 문구는 src/muhan/datapatch/log 에 있고,
    설치할 때 서버의 파일이 원본 그대로일 때만 바꾼다 (서버에서 고친 내용은 덮어쓰지 않는다).
  데이터 경로가 실행 파일에 들어가므로, 설치 디렉터리를 바꾸려면
% /home/olddos/olddos-bbs/src/muhan/update.sh /다른/설치/디렉터리

3) 끄기 / 켜기
% /home/olddos/muhan/bin/killmud          끄기 (접속자 저장 후)
% /home/olddos/muhan/bin/killmud -r       다시 띄우기
% cd /home/olddos/muhan/bin && nohup ./startmud > /dev/null 2>&1 &     꺼 둔 것 켜기
  부팅 때 자동 실행: /etc/rc.local 에
  su - olddos -c 'cd /home/olddos/muhan/bin && nohup ./startmud > /dev/null 2>&1 &'
  로그: /home/olddos/muhan/log/ (log, startmud.log, frp.out)

4) 운영자
  게임에서 '하늘소' 로 캐릭터를 만들면 접속할 때 운영자(DM) 가 된다.
  운영자 이름은 game/src/mtype.h 의 DMNAME.
  운영 방법은 src/muhan/game/DM.DOC 와 game/docs 를 참고 (EUC-KR).

네이버 카페 글 가져오기 (운영자 메뉴 14)
==============
운영자 메뉴 14 (bin/cafeimport)
  1. 카페 글 받기   글 번호 범위(예: 103001-103050 103100)를 넣으면 제목/작성자/본문/그림/첨부를
                    data/cafe/download/<글 번호>/ 에 받아 둔다. BBS 는 아직 바뀌지 않는다.
                    (body.txt 는 BBS 에 들어갈 본문. 서버에서 직접 고쳐도 된다)
  2. 받은 글 확인   목록, 번호로 본문 보기, D 번호 로 빼기
  3. BBS 에 올리기  받아 둔 글을 게시판에 올리고, 올린 글은 받은 폴더에서 지운다
  4. 카페 회원 연결
  댓글은 가져오지 않는다. 본문 끝에 카페 원문 주소를 붙인다.
  명령줄: HANULSO=/home/olddos/olddos-bbs bin/cafeimport - fetch 103001-103050 / list / show 번호 / drop 번호 / apply

1) hanulso.cfg 에 추가 (git 에 올라가지 않는 파일)
  <naver>
    <cafe_id>28655511</cafe_id>
    <cookie>NID_AUT=...; NID_SES=...</cookie>
  </naver>
  쿠키 얻기: PC 브라우저에서 카페 매니저 계정으로 네이버에 로그인 ("로그인 상태 유지")
    -> F12 개발자 도구 -> Application(애플리케이션) -> Cookies -> https://cafe.naver.com
    -> NID_AUT, NID_SES 의 값을 복사.  쿠키는 비밀번호와 같으니 남에게 보이지 않게.
  쿠키가 만료되면 가져오기가 멈추고 "로그인이 되어 있지 않습니다" 라고 알려 준다. 다시 넣으면 된다.

2) 메뉴 대응표: table.txt (hanulso.cfg 와 같은 폴더)   ("카페 메뉴 번호  게시판 테이블")
  받을 때는 메뉴와 상관없이 모두 받는다. 게시판은 BBS 에 올릴 때 이 표로 정한다.
  대응이 없는 메뉴의 글은 올리지 않고 받은 그대로 둔다 (표에 넣고 다시 올리면 된다).
  카페 메뉴 번호는 '받은 글 확인' 이나 올릴 때 "건너뜀: 메뉴 167 [구매]합니다!" 처럼 보인다.

3) 작성자
  네이버는 카페 매니저에게도 회원 아이디를 가려서 준다 (coma****). 그래서
  - 닉네임이 같거나, 아이디가 카페 닉네임과 같은 BBS 회원이 한 명이면 그 회원의 글로 올린다 (자동 연결).
    둘 이상이면 가려진 아이디(coma****)의 앞부분이 맞는 회원이 한 명일 때만 연결한다.
    아이디 앞부분까지 다르면 data/cafe/link_check.log 에 남긴다 (확인용).
  - 없으면 가려진 아이디로 회원을 만들어 올린다. 이 회원은 로그인할 수 없다 (비밀번호 '!').
    가려진 아이디가 다른 사람과 겹치면 coma****2 처럼 나눈다.
  - 운영자 메뉴 14 -> 4 "카페 회원 연결" 에서 후보를 보고 BBS 아이디로 연결하면,
    이미 올라간 글/첨부도 그 회원 것으로 옮긴다.
    M: 예전 restore 프로그램으로 가져온 juya**** 같은 회원의 글을 BBS 회원으로 옮기기.

  - 운영자 메뉴 14 -> 5 "올린 글 고치기": 이미 올린 글의 본문을 카페에서 다시 받아 덮어쓴다.
    글 번호/조회수/첨부는 그대로. 예전 받기(서버 lynx)로 본문 한글이 깨진 글을 고칠 때 쓴다.
    번호를 비우면 data/cafe/imported.log 의 글 모두.
    예전 방식으로 받아 두고 아직 안 올린 글은 article.json 으로 본문을 저절로 다시 만든다 (다시 받지 않음).

4) 기록 (data/cafe/, git 에 올라가지 않음)
  download/      받아 두고 아직 올리지 않은 글
  imported.log   BBS 에 올린 카페 글 번호 (hanulso.cfg 옆의 restore.log 도 함께 읽어 다시 가져오지 않음)
  members/ assigned/ links/   카페 회원 -> BBS 아이디
  unlinked.log   연결 후보,  attach_unknown.log  읽지 못한 첨부 정보

5) 보안: 예전 restore 프로그램(지금은 지움)은 카페 작성자 회원을 비밀번호 12345678 로 만들었다.
  그 회원들(아이디에 * 가 있음)은 누구나 로그인할 수 있으므로 한 번 막는다:
  mysql> UPDATE member SET PASSWORD='!' WHERE USER_ID LIKE '%*%';
